# Browsey 1.0.2

Release date: 2026-09-25. Target: Linux x86_64.

## Highlights

- USB formatting to exFAT, FAT32, ext4, and btrfs, drive Properties, user ownership
  on newly formatted Linux filesystems, and device-scoped progress. Lost UDisks
  replies are treated as uncertain completion, never an automatic erase retry.
- MTP phone discovery through GIO and on-demand mounting without opening Nautilus.
  Unlock the phone and enable USB file transfer. Phone Properties are informational.
- Visible-first thumbnail scheduling, cancellation of stale work, cache reuse,
  bounded workers, improved JPEG decoding, and recent-use/byte-budget eviction.
- Ctrl + wheel zoom from list into five grid sizes: 64, 96, 128, 160, and 192 px.
  Zoom is per window and resets on restart. Cozy/Compact gaps are 8/6 px.
- System/Omarchy colors in Settings and a separate 16% opacity lasso fill.
- Item-based delete/trash progress, clearer persistent errors, keyboard-accessible
  context menus, and improved dialog focus handling.
- Streaming UnRAR extraction of compressed RAR4/RAR5 and complete multi-volume
  sets, retaining path checks, size limits, cancellation, and rollback tracking.

The previous published GitHub assets were v0.4.6. This release also includes the
1.0.0 Linux-hardening work and 1.0.1 file-operation safety fixes. Read
[CHANGELOG.md](../../CHANGELOG.md) for the intervening history.

## Packages and dependencies

RPM and DEB packages are built from the release tag on Ubuntu 22.04 through
`.github/workflows/release-linux.yml`, rather than on a rolling-release desktop.
This follows [Tauri's Linux packaging guidance](https://v2.tauri.app/distribute/debian/)
to avoid requiring a newer glibc than the intended target systems.

Download the package for your distribution and `SHA256SUMS` from
[GitHub Releases](https://github.com/chl84/Browsey/releases/tag/v1.0.2).
Verify the matching checksum before installing. These packages are not signed.

```sh
# Ubuntu/Debian-family (use the exact downloaded filename)
sudo apt install ./Browsey_1.0.2_amd64.deb
# Fedora
sudo dnf install ./Browsey-1.0.2-1.x86_64.rpm
```

- GTK 3 and WebKitGTK 4.1 remain required; the frontend and PDFium are bundled.
- USB formatting needs UDisks2, a PolicyKit authentication agent, and the matching
  `exfatprogs`, `dosfstools`, `e2fsprogs`, or `btrfs-progs` tools.
- Phones need the distribution's GVFS MTP backend (`gvfs-mtp` on Arch/Fedora;
  `gvfs-backends` on Ubuntu), a working session bus, and USB file-transfer mode.
- Video thumbnails require ffmpeg. Cloud features require separately configured
  rclone and are opt-in.
- No Windows installer or macOS build is published for 1.0.2.

## Validation scope

Existing Linux 1.0 signoff records remain historical evidence, not a claim that
every Fedora/Ubuntu manual acceptance scenario was rerun for this patch.

Local checks on 2026-09-25:

- Rust formatting, all-target/all-feature check, Clippy with warnings denied,
  and the backend typed-error guard passed.
- Backend suite: 471 passed; the opt-in private-bus timeout/progress test also
  passed separately (26 seconds, no physical USB device used).
- Frontend unit suite: 190 passed; all 23 Playwright scenarios, lint, typecheck,
  and the production frontend build passed.
- Docs lint, typecheck, production build, and all 20 strict consistency checks
  passed.
- Semgrep is not installed locally; the Rust Quality workflow runs both the
  advisory and blocking rules before publication.
- The docs dependency audit reports 14 advisory entries (9 high, 3 moderate,
  2 low). These include build/dev tooling and Svelte runtime advisories; they
  have not been remediated in this version-only release preparation. The docs
  are a static client-rendered site with repository-owned content, not an SSR
  service or an exposed Vite dev server. A dependency/security update remains
  follow-up work; this is not a claim of a clean security audit.

The release's GitHub Actions runs provide the package-build and smoke-test
results. Publication requires both native artifacts, matching checksums, and
green quality workflows; the workflow does not publish automatically.

Physical USB formatting is destructive and was not rerun as part of packaging.
The automated USB timeout test uses a private simulated D-Bus service. MTP and
thumbnail tests use synthetic fixtures/mocks; they do not touch phone files.
Recent user testing confirmed phone discovery and browsing on Omarchy, but this
is not a device-compatibility matrix or a measured thumbnail-speed guarantee.

## Limitations and upgrade notes

- Back up important data before destructive file operations or formatting.
- Newly formatted ext4/btrfs volumes get user ownership; existing volumes are
  not automatically re-owned or repaired.
- MTP/GVFS latency and temporary I/O errors depend on the phone/backend. Keep the
  phone unlocked and inspect connection state before retrying failed navigation.
- Password-protected RAR files report an error; there is no password prompt yet.
- Cloud deletion is permanent, with no cloud trash or undo/redo.
- RPM/DEB package downgrade is not a supported upgrade path.

## Maintainer publication procedure

1. Update Cargo version/lockfile, RPM metadata, AppStream, README, changelog, and
   docs-site release notes; run the strict maintenance suites and docs checks.
2. Commit, push `main`, and create/push the matching annotated release tag.
3. Dispatch `Linux Release Bundles` with that tag. The workflow checks version
   consistency, builds packages, inspects metadata/dependencies, and smoke-tests
   the extracted DEB binary without a development server.
4. Review quality workflows and download the release artifact. Verify SHA256SUMS
   and inspect package contents. Do not replace assets from older releases.
5. Create a draft release, upload both packages and SHA256SUMS, review notes, then
   publish. Publish only files built from the exact release tag.
