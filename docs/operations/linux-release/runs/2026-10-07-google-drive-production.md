# Google Drive installed-build acceptance

Date: 2026-10-07, 20:24–20:46 UTC. The maintainer explicitly authorized Google
Drive testing on the production build. This is bounded functional acceptance,
not completion of the expanded provider checklist or a performance budget.

## Build and isolation

The installed Browsey 1.0.4 executable was used directly, without rebuilding,
replacing the installation, enabling `native-test`, or injecting test IPC.
Its SHA-256 was
`244152d699e252bf2425152a879f0080a5f19f240c70fb8c2dfcd27127110622`,
matching `target/release/browsey`. The clean checkout at observation was
`3fab6c445ccb9ef74bd481f60d9dbe7d8cbe6794`; this records checkout context rather
than an independently embedded binary source revision.

Environment: Omarchy 4.0.4, Linux 7.2.5, rclone 1.75.1, native WebKitGTK on
Hyprland. A private XDG profile under `/tmp` isolated settings, caches, working
copies, MIME handlers and undo storage from the normal Browsey profile.
AT-SPI actions and compositor keyboard input checked the executable, PID and
private data directory and targeted only the owned production window.

Authentication used the existing rclone configuration in place. No credentials
were copied or committed. Setup created one unique generated directory on the
configured Google Drive remote, verified it was empty and uploaded an ownership
marker. All cloud writes stayed inside that directory. Independent rclone reads
verified results; they are supplemental checks, not substitutes for native UI
operations. Account names and personal file listings are omitted here.

## Test-harness corrections

Initial attempts needed Norwegian slash/colon key mapping, pacing of window-bound
input, actual accessible dialog names and retries for transient AT-SPI nodes.
Paste requires focus in the file pane rather than the address field. Navigation
must wait for destination-specific entries; breadcrumbs are hidden while the
address field has focus. One premature paste copied a generated local file to
the same local test folder; the corrected 8 MiB cloud workflow passed.

The first extraction assertion incorrectly expected the ZIP stem as the output
folder. The archive engine returned a unique `tree-extract-…` directory. The
corrected assertion discovered that output and verified its bytes and empty
directories. These failed harness assertions are not counted as successful
workflows or as confirmed application defects.

A directory's appearance in the trashed-only listing was insufficient evidence:
that listing also exposed active directories. The normal-trash assertion was
therefore repeated using a separate generated file and `--files-only`.

## Cleanup and remaining scope

The final production window closed normally. The private Browsey process and
its private rclone daemon were confirmed stopped. Cleanup downloaded and checked
the ownership marker, then moved only the generated cloud directory to normal
trash with `--drive-use-trash=true`; its active entry was verified absent.
No account-wide trash purge, existing-file deletion or settings change occurred.
Private local evidence and generated working copies remain under `/tmp`.

Not tested in this run: advanced rename, duplicate-name/case conflicts,
changed cloud sources, concurrently created upload targets, active cancellation,
network failures, real quota/rate limits, external drag receivers, provider-web
restore or large/deep-tree performance. The 8 MiB result establishes exact
transfer behavior for that fixture, not a general large-file budget.

The [Google Drive checklist](../../../cloud/checklists/google-drive-rclone-manual-checklist.md)
and the parent C6 acceptance requirement remain partially open.

The later [provider-difference run](2026-10-07-google-drive-provider-differences.md)
passed case-sensitive names, advanced rename, native documents and shortcuts,
but reproduced an unresolved integrity defect: two identical-name objects
collapse into one row, and copying the displayed 47-byte object downloads
the other object's 24 bytes. The broad successes above do not certify
ambiguous Google Drive paths.
