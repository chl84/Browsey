## Native File Workflow

copied them to an empty fixture directory, and compared both resulting file
contents against the sources. Both sources remained intact. Native Ctrl+Z removed
the copied outputs; Ctrl+Y restored both verified contents. This supplies selected
installed evidence for `CO-LCM-001` and `CO-LCM-002`, not all conflict/cancel/UI
conditions in those matrix rows.

focus before/after input. Later selection/move attempts lost desktop focus and
were aborted or inconclusive. Their commands and filesystem assertions do **not**
count as native move/rename/undo passes. Direct PID-specific AT-SPI actions were
used for subsequent Settings inspection, without continuing global keyboard input.

## Process Interruption and Recovery

Fresh `killed` tests pass for clipboard overwrite interruption and cleanup after
killed ordinary/protected undo sessions. The clipboard test covers 12 combinations:
copy/forced move, flat/nested merge, and prepared/backed-up/first-write boundaries.
They kill real test subprocesses at controlled seams and run independent cleanup
processes. This verifies process interruption, not a whole GUI process killed
during an uninstrumented transfer, kernel power loss or physical unplug.

For installed acceptance, the existing `held_session_child` helper created a
protected session under the isolated production profile. It was killed only
after reporting marker readiness. It uses the real backup/marker implementation
but is a generated recovery example, not a failed operation against personal data.

Installed Settings reported 551 B, six files, three sessions, one marked session;
an independent metadata walk matched all four totals. After stopping idle test
instances and restarting the installed app with the same isolated profile,
Settings reported 367 B, two files, one marked session. The original
`owned-backup` content and marker survived; only abandoned unmarked test sessions
were pruned. These totals include marker-file contents and exclude sibling locks.

The installed expandable guidance says to finish operations/close app instances,
avoid old builds that ignore markers, copy needed data to a separate safe folder,
verify contents, and not remove markers just to free space. Following that guidance,
copied the generated backup to an empty separate fixture directory after verifying
all five test app PIDs had exited, verified exact contents, and left the original
backup and marker intact. An earlier copy while the test app was idle was not the
close-all-instances guidance check. The panel itself has no
restore/delete/clear-marker control. It does not recreate the in-memory undo stack.

See [undo scope](../undo-scope.md) and the
[verified safety archive](../../../todo-archive/TODO_DAILY_DRIVER_SAFETY_COMPLETED.md)
for action/history and retained-partial-output boundaries. Metadata receipts and
readback are not atomic tree snapshots; uncertain failures can retain partial
copies and protected originals rather than overwrite competing files or retry.
