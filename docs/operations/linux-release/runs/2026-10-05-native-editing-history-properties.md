non-empty folder copy/cut/paste through keyboard and context menus, rapid repeated

[documented undo scope](../undo-scope.md). It checks move, rename, supported
permanent deletion of a nested directory and overwrite, each with independent

A completed new action is then retained across one owned app restart while both

are reused; all old driver/candidate identities must finish confirmed teardown
before a new session is allowed. A failed closure cannot trigger another launch
or automatic retry. All restart identities and closure stages stay in the report.

NT1-8 covers one generated file, a non-empty folder and mixed selection in list
and grid. It checks Basic size/type/selection, Extra, Ownership, Permissions and

include the selected directory itself);
permission checkbox states come from independent owned-file metadata. Unsupported

No permission/ownership control is changed, no principal catalogue is approved,
and no drive root or personal file metadata is opened.

## Fixes and regressions

Properties previously presented unmeasured cloud directories as zero bytes, or
presented only selected-file bytes as the total when cloud directories were also
selected. These totals now stay unknown instead of claiming a complete measured
size. The same rule preserves unknown mixed local/virtual directory totals.
All-virtual selection keeps unsupported permissions without sending cloud paths
to local permission inspection. Two regressions failed before the size fix and
passed after it; native cloud directory/mixed checks expect an unknown total,
not a fabricated empty-folder value. Recursive cloud size computation is outside
this increment.

Rename retained its previous rejection error while a corrected request awaited
the backend. The controller now clears that stale error before waiting, matching
creation dialogs. A regression failed before the fix and covers the corrected
pending request, suppression of repeated submission and successful closure.

Native WebKit input diagnostics observed a secondary mousedown/contextmenu
followed by a misreported primary mouseup/click. This collapsed an existing mixed
selection before the context action ran. Row input now checks the original
gesture button as well as the click, retaining keyboard activation and subsequent
real primary clicks. The selection controller also refuses ordinary non-primary
clicks. Regressions cover both sequences and retain primary single/toggle/range
selection. The harness checks selection immediately after opening a selected
entry's context menu, then checks the actual transfer tree. Temporary passive
event capture was removed after diagnosis; native input remains real input.
Review also found that ignoring the synthetic click must clear the previous
double-click candidate. A regression failed before that correction: a quick
primary click after a context gesture incorrectly opened the item. The corrected
sequence preserves selection and still allows the next genuine double click.

A successful rename removes its original trigger row. Modal focus previously
returned nowhere when that element disconnected. ModalShell now captures the
original focusable ancestor as a fallback and uses it only if the trigger is
gone and no other connected control owns focus. Component regressions cover a
removed trigger and preserving focus on another connected control. Native closing
checks require the same owned collection or selected entry, not body/another view.
OneDrive's background refresh exposed another timing case: the old trigger can
still be connected at dialog close, then disappear when refresh finishes.
Rename now explicitly returns focus to its stable collection before that removal.
A component regression failed before the correction and verifies focus survives
later trigger removal. Other dialogs retain their existing target-first policy;
restoration still respects another connected control that already owns focus.

The permanent-delete dialog now distinguishes supported local Undo, limited to
the active app session, from irreversible cloud/network deletion. Its component
regression checks those boundaries; the existing network warning remains precise
about direct deletion without downloading a local backup.

The first five-provider run reached USB Properties and displayed zero bytes and
zero items for a generated non-empty folder. Recursive sizing excluded every path
below `/run`, including explicitly selected USB/GVFS folders. A synthetic owned
fixture reproduced the zero result before the fix. Sizing now honors an explicit
selection inside runtime/temporary trees while ancestor scans keep excluding
those trees. Kernel/device pseudo-filesystems remain excluded even when selected;
regressions cover both that rule and path-component boundaries. Native independent
readback checks the generated folder bytes/counts after rebuilding the candidate.

OneDrive resolves a differently cased destination to the source itself, so the
transfer overwrite guard wrongly rejected case-only renames. The backend now
recognizes only same-parent moves with otherwise identical names on explicitly
case-insensitive providers. Copies, different parents/remotes and existing
objects on case-sensitive providers keep the destination-exists guard.
The fake-rclone fixture has an opt-in case-insensitive metadata lookup; the
file/folder regression failed before the fix and passed after it with nested
bytes intact. A separate regression preserves copy, other-parent and Google
Drive destination collisions. The native retest accepted file casing but revealed that rclone `moveto` treats
the directory case-only roots as overlapping. The folder path now uses two
planned sibling moves through a preflighted unique temporary name, following
[rclone's directory case handling](https://github.com/rclone/rclone/blob/v1.75.1/fs/operations/operations.go#L2365).
Each stage disables CLI retries; neither failed stage is retried or rolled back.
An incomplete-rename error lists source, temporary and destination recovery paths.
Synthetic failures at each stage must preserve the nested bytes and unrelated
file and must make exactly the planned number of write calls. The fake's direct
case-only folder move reproduces the native overlap rejection before this fix.

Native MTP case-only rename returned the same object twice in directory
enumeration. Its shared no-replace move path now routes only same-parent,
case-only MTP names through two distinct sibling names, retaining the existing
no-follow/no-replace/snapshot safeguards. Ordinary local and other-provider
moves use the existing path. An occupied destination must stop before the first
write. A failed stage retains generated source/temporary/destination recovery
paths without a retry or rollback. The shared path also covers later Undo/Redo
of such a rename, although native mobile history is outside this acceptance.
Synthetic tests cover route boundaries, nested/empty-directory preservation,
occupied destinations and failure at either stage. The original native FAIL
remains retained. Fresh native acceptance must retain the strict duplicate check.

Harness corrections distinguish expected no-selection rejection, the actual
mixed file/folder selection count and Ctrl+P. Properties rows use `display:
contents`; checking the row's own box hid its visible children from verification.
The driver now reads visible label/value children and compares exact numeric
totals/counts independently of DOM whitespace. Policy regressions reject hidden
tab values, wrong totals/counts/units and unknown values for a measured file.
Independent tree verification now runs at most two read-only operations at once,
following the existing creation suite's settled-pair rule. Directory enumeration
and byte reads remain complete after every attempt. Both started siblings must
settle before a failure is reported, and later reads must not start after that
failure. Regressions check that bound/wait, exact tree corruption and refusal of
an observed prefix sibling before any content read. Mutation dispatch remains
single-attempt; only independent reads are parallelized. Cloud metadata must match
before byte reads begin. A successful but stale listing is polled at most four
times, with one-second gaps and the existing 45-second per-CLI-call limit.
Unexpected directories are recorded but not traversed; byte failures and
corruption are never retried. Regressions cover a transient deleted-directory
listing, damaged bytes after exactly one content read, the persistent-stale
four-snapshot bound and a failed metadata call stopping after one attempt.
