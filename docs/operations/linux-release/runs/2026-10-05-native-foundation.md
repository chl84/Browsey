## Completed increments

- [x] **NT0-2:** Six Rust scope regressions passed with `--features native-test`.
  Invalid mixed sources, traversal, prefix siblings, URI/implicit-path aliases,
  unsafe rename names, unknown commands and global network-trash requests are
  denied before the injected metadata callback is reached. Generated actual
  fixtures verify replaced, nested and broken symlink rejection and preservation
  of an in-tree sentinel. This does not establish atomic defense against path
  replacement during I/O.
- [x] **NT0-3 / input-local:** One-layout acceptance, as explicitly narrowed by the
  maintainer. Norwegian input verified an owned address containing `/`, `_` and
  `æøå`, created an empty Unicode-named file and renamed another file without
  changing its 3,456 generated bytes. Focus/value checks precede Enter. The case
  first cancels Shift+Delete, then types; modifiers are released explicitly.
- [x] **Local foundation:** `create-local`, `rename-local`, `delete-local`,
  `copy-within-local`, `move-within-local` and `undo-copy-local` passed.
  Each transfer checks an individual file and a nested directory child, with
  independent destination bytes and source preservation/removal checks.
- [x] **AT-SPI:** The exact candidate's File list was exposed; permanent-delete
  cancellation used its accessible Cancel action. Candidate executable, PID and
  private profile were checked. Session close and both owned process exits were
  confirmed. Together with input and foundation, the local run has eight PASS cases.
- [x] **Focused harness checks:** All seventeen Node policy/orchestration/input
  regressions and native ESLint passed. Synthetic tests reject an altered binary,
  stale/untracked build inputs, another commit and old manifests. They also
  verify setup failures are associated with a declared case before UI operations.
  Strict documentation consistency also passed all twenty checks, and local
  documentation links and `git diff --check` passed. These checks are not native
  provider acceptance.

The underscore failure came from native WebDriver text delivery. The helper now
uses actual W3C key actions, including explicit Shift for `_`, and verifies exact
text before any file-operation submission. Address-field hit testing avoids
clicking an overlapping breadcrumb. Temporary US was authorized and tried; it
did not resolve the driver mismatch. Original Norwegian configuration and a clean
Hyprland configuration-error result were restored. WebKit exposes no EditableText
interface for the tested field, so no AT-SPI text replacement is used. Non-BMP
emoji delivery remains excluded; NT4-1 is open.

## Provider runs

The initial rebuilt candidate passed five within-provider foundation cases on
local disk, USB and network, plus create/rename/delete on OneDrive. It stopped
during independent readback in `copy-within-cloud`. A subsequent read-only check
of that exact generated destination returned the expected 3,456 bytes, but the
failed run was not converted to PASS and no mutation was repeated in that run.
Its mobile, remaining cloud and cross-provider cases were not reached.

The five-provider follow-up with the final candidate again stopped in
`copy-within-cloud`, with independent `rclone cat` exit 3 (overall BLOCKED).
Read-only inspection of that exact owned fixture confirmed the individual file
at the destination contained the expected bytes, while the nested directory was
absent and the source directory/child survived. The candidate screenshot shows
`Paste failed: Cloud operation failed`. This is a reproduced cloud directory-copy
failure, not successful acceptance based on the individually copied file.
The final local/cloud control run, using the clipboard/error-observation harness,
passed local input and five local foundation cases and cloud create/rename/delete.
It stopped in `copy-within-cloud` with an explicit `APP_REPORTED_ERROR` in the UI
phase: `Paste failed: Cloud operation failed`. Its overall result is FAIL;
owned candidate/driver teardown is PASS. Cloud move, routes and local undo in
this partial run are NOT_RUN. The earlier dedicated local undo acceptance stands.

A separate four-provider run explicitly deferred cloud so mobile was reached.
It passed create/rename/delete on mobile and initially recorded copy PASS, then
failed source removal in `move-within-mobile`. Later read-only checks still found
both source and destination file bytes. Clipboard readiness was not yet observed
in this run; this alone does not establish an app defect in mobile move.

The next local/mobile run waited for a fresh `Copied`/`Cut` toast and cut-row
styling before navigation/paste, and for the destination row before readback.
It reproduced a delayed mobile directory-copy error: setting directory
permissions returned `Operation not supported` (95), and cleanup retained a
non-empty destination directory (39). The error refers to the preceding copy
fixture, but was observed during the next move case. Consequently the raw
`copy-within-mobile` PASS is withdrawn from acceptance; move completion is not
accepted either. This is an important remaining case-attribution/readiness
limitation: the visible activity can disappear before the final backend error.
The overall run is FAIL and owned teardown is PASS. No mutation was retried.
Subsequent read-only checks of this exact mobile copy fixture found the source
file, source child, destination file and destination child still readable with
the expected 3,456 bytes each. Retained destination content does not reverse
the permission/cleanup failure or establish complete copy semantics.

## Remaining scope

NT0-4 has bounded driver shutdown, signaled-exit detection and a fail-closed
teardown result, but occupied-port/crash/closure/timeout fault coverage is still
open. NT0-5 now declares per-case provider dependencies and records setup failures
and remaining NOT_RUN cases; fixture-tool failures are BLOCKED, not automatically
classified as reproduced app defects. Capability declarations, partial-batch
coverage and pre-run setup-reporting completeness remain open.
Delayed failure attribution and observing the backend's final reply independently
of the activity timer remain part of NT0-5. Destination bytes and an idle-looking
frame alone cannot close a case that subsequently reports an operation error.

No A0/A1 parent row is checked by this run. Exclusions: watcher behavior,
drag/drop, personal clipboard/trash, formatting, mount/connect/disconnect and
reconnect, large-file progress/cancellation, conflicts/overwrite recovery,
archives/passwords, non-BMP text entry, other keyboard layouts and distributions.
Private fixtures/recovery evidence are retained without automatic cleanup.
